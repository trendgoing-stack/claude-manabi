# 「やってみよう」課題を書くための共通の指示（作成エージェント向け）

学習アプリ「Claudeまなび帳」の演習タブ「やってみよう」に載せる、実際に手を動かす課題を作る。リポジトリ：このリポジトリの直下。

## 先に読むもの

1. `js/types.js` の `TryTask`（課題の形式）と `CONTENT.md` の 8・9 節
2. 担当する章の解説 `data/text/<章>.json`（課題は解説の内容に沿わせる。解説に書かれていない操作を課題にしない）
3. 必要に応じて、その節の `sources` の公式ページ（WebFetch）

## 形式

`work/try-<部>.json` に `{ "schemaVersion": 1, "tasks": [ … ] }`（部：`a` または `c`）。各課題：

| フィールド | 書き方 |
|---|---|
| `id` | `try-<章番号2桁>-<連番2桁>`（例：`try-04-01`、`try-13-02`） |
| `title` | 何をするか（例：「CLAUDE.md を作って、Claude Code が読んでいることを確かめる」） |
| `surface` | 主に使う場所を1つ：`web`／`desktop`／`mobile`／`cli`／`ide`／`chrome` |
| `minutes` | 所要時間の目安（分、5〜20） |
| `goal` | 何を確かめる課題か（1〜2文） |
| `steps` | 手順（3〜7個）。具体的に、そのまま試せるように。指示の文例は「」で書く |
| `expected` | 期待する結果（どうなれば成功か。画面の細部や文言は変わりうるので、ふるまいで書く） |
| `cautions` | 注意（0〜3個）。安全・データ・権限に関わること、プランによって使えない場合があること |
| `sectionIds` | 関連する解説の節の id（1〜3個） |

## 方針

- **すべて練習用のフォルダやリポジトリ、練習用のチャット・プロジェクトで行う前提で書く**。手順の最初で「練習用の〜を用意する」と書く
- 本番のリポジトリの削除、強制 push、API キーなどの秘密情報を扱う操作、お金・購入・送信を伴う操作、他人に影響する操作（共有・公開・メール送信など）は課題にしない
- 料金・利用上限・プランごとの条件は書かない。プランによって使えないことがある機能は cautions で「使えない場合はとばしてよい」と書く
- 1章あたり1〜2件。読者が「本文で読んだことを確かめられる」課題にする

## 自己検査

`node tools/check-try.mjs <部>` を通す。`work/` 以外は変更しない。

## 報告

10行以内：件数、章ごとの件数、判断に迷った点。
