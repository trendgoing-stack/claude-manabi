# 解説 1章の事実の検査（検査エージェント向けの共通の指示）

学習アプリ「Claudeまなび帳」の解説1章分・クイズ・用語を、作成者とは別の立場で、公式情報と照合して検査する。リポジトリ：このリポジトリの直下。対象ファイルは読むだけで、**編集しない**。

## 対象

- `work/<章id>-draft.json`（章）、`work/<章id>-quiz.json`（クイズ）、`work/<章id>-terms.json`（用語）
- 決まりは `CONTENT.md` の 2〜9 節

## 検査の観点

1. **事実の照合（最重要）**：全節・全問・全用語について、記述を公式ページ（各節の `sources`、必要なら同じサイトの関連ページ）で確かめる。Claude Code は `https://code.claude.com/docs/en/<ページ>.md`、ヘルプセンターは `https://support.claude.com/en/articles/...`。公式に書かれていない断定、古い仕様、機能名・コマンド名・ファイル名・設定名の誤りを挙げる。確認できなかった記述は「確認できなかった」と明記する
2. `surfaces`（使える場所）と `status`（提供状況）が公式の記述と合っているか
3. `sources` の URL が実在し、その節の根拠になっているか（日本語版の URL が開けるか）
4. 変わりやすい数値（料金、利用上限、サイズ・個数の上限、プランごとの提供条件、期限）が書かれていないか
5. 公式の文章・例・図を転載した、または言い換えて並べただけの箇所がないか
6. クイズ：正解が公式情報に照らして正しく、誤りの選択肢が明確に誤りか。仕様変更ですぐ誤りになる問い（「〜はできない」など）、料金・上限を問う問いがないか。解説が正しいか
7. 用語：定義が正確か、既存の用語と重複していないか
8. 初めて使う人に誤解を招く表現、安全に関わる注意の抜け（権限、データの削除、秘密情報など）
9. 日本語として不自然な箇所、章内の表記の揺れ（minor でよい）

## 出力

`work/<章id>-qa.json` に JSON で書く：

```json
{ "chapter": "<章id>", "checkedAt": "YYYY-MM-DD",
  "sections": [ { "id": "<節id>", "result": "ok|fix|unverifiable", "note": "照合した結果の要約（1〜2文）" } ],
  "findings": [
    { "target": "<節id> または <問題id> または <用語id>", "blockIndex": 数または null,
      "severity": "blocker|major|minor",
      "issue": "何が問題か", "evidence": "根拠（公式ページの URL と、該当する内容の要約）",
      "fix": "『元の文言』→『新しい文言』 の形の修正案。削除なら『元の文言』→（削除）" }
  ] }
```

- `sections` には全節を入れる。`unverifiable`＝その節の中心の記述を公式情報で確かめられなかった
- blocker＝事実の誤り・料金や上限の記述・転載、major＝誤解を招く／公式で確認できない断定／クイズの正解が不確か、minor＝表現の改善
- 一時ファイルが必要なら `work/<章id>-qa-` で始まる名前にする

## 報告

10行以内：節ごとの結果の件数（ok／fix／unverifiable）、指摘の件数（severity 別）、blocker と major の要点だけ。
