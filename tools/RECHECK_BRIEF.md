# RECHECK_BRIEF.md — 情報の鮮度の点検の手順

Claude の機能は頻繁に変わるため、解説の節と辞典の項目を定期的に公式情報と照合し直す。目安は90日ごと（アプリの「古い可能性」の警告と同じ）。

## 手順

1. **対象を一覧にする**
   ```
   node tools/stale.mjs 90
   ```
   `checkedAt` が90日を超えた節と項目が、確認日の古い順に、照合に使う英語版の公式ページと一緒に出る。日数は引数で変えられる（`--all` で全件）

2. **前回の点検以降の変更を確かめる**
   - Claude Code：`https://code.claude.com/docs/en/whats-new/index.md` と `changelog.md`
   - Claude アプリ：ヘルプセンターのリリースノート `https://support.claude.com/en/articles/12138966-release-notes`
   - 変更のあった機能に関係する節・項目は、日数に関係なく対象に加える

3. **対象を公式ドキュメントと照合し、直す**
   - 作成と検査の手順（CONTENT.md の 10 節）と同じく、照合は作成者と別のエージェントに任せてよい。対象の節・項目の id と、2 の変更点を渡す
   - 変わっていた記述を直し、`checkedAt` を照合した日にする。`verification` は `doc-verified`（ユーザーが操作して確かめたものは `tried`）
   - 公式で確かめられなくなった記述は削るか弱める。節の中心が確かめられなくなったら `unverified` にする（その節のクイズは出題されなくなる）
   - 関係するクイズの問題・用語・辞典の項目・「やってみよう」の課題も合わせて直す
   - 料金・利用上限などの数値は、変わっていても書き足さない

4. **新しい機能を見つけたら、報告にとどめる**
   - 章や節を勝手に追加しない。「追加の候補」として、機能名・公式ページ・入れるならどの章か、をユーザーに報告する

5. **検証して公開する**
   ```
   node tools/validate.mjs
   ```
   エラーがなくなったら、`data/meta.json` の `dataVersion` と `sw.js` の `VERSION` を同じ値で上げ（`YYYY.MM.DD-n`）、コミットして push する。HANDOFF.md に点検した日と件数を書き残す
